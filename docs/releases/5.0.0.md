# 5.0.0 — the SDK talks to the control plane

**Status: PREPARED, NOT PUBLISHED.** See *Why this is not on Maven* below.

## The defect this release fixes

Through 4.x the SDK read a `product_remote_config` table over PostgREST from a Supabase project
the consumer supplied. The control plane in this repo serves `GET /v1/configs` from an entirely
different schema. They were two incompatible systems living in one repository, so **an operator
could edit a config in the dashboard and no device would ever see it.** Nothing reported the
mismatch: the old client caught every exception and returned an empty list, which is
indistinguishable from "nothing to show".

## Breaking changes

### Initialization

`supabaseUrl` and `supabaseKey` are **gone**.

```kotlin
// 4.x
remoteConfig {
    supabaseUrl = "https://xyz.supabase.co"
    supabaseKey = "eyJ…"
}

// 5.0.0
remoteConfig {
    publishableKey = "rck_live_…"   // issued per app+platform in the dashboard
    packageName = "com.your.app"
    platform = "android"
    appVersion = "1.4.0"
    certDigest = "AB:CD:…"          // Android only, when the key pins digests
    httpClient = yourKtorClient     // injected; this library ships no engine
}
```

`baseUrl` defaults to the hosted control plane and is only set when self-hosting.

The `HttpClient` is injected rather than constructed internally. That keeps this library free of
a platform HTTP engine across fifteen targets, and lets an app that already tuned a client
(timeouts, proxy, certificate pinning) keep using it.

### A fetch has three outcomes, not two

```kotlin
when (val result = service.fetchConfigs(screen = "home")) {
    is ConfigFetchResult.Success     -> result.envelope.configs   // may legitimately be empty
    is ConfigFetchResult.Rejected    -> log(result.code)          // key_invalid, package_mismatch, rate_limited…
    is ConfigFetchResult.Unavailable -> serveCache()              // transport failure
}
```

`Rejected` is separate from an empty `Success` deliberately. An integrator with a revoked key
now learns that instead of watching their product silently show nothing.

### The wire model

`RemoteConfigEnvelope` / `RemoteConfigItem` replace the flat 4.x shape. Each item carries a
`template` id, an **opaque** `payload`, and a `display`. The payload is not flattened into named
fields because the fifteen builtins genuinely disagree about their contents —
`update_available` carries store_url / forced / release_notes / current_version and has no title
or body at all, so any fixed field set is wrong for most templates.

### Targeting moved to the server

Platform, app-version window, screen and schedule are evaluated **server-side**. A config that
reaches a device has already matched. `RemoteConfigEvaluator` therefore got smaller: it now
applies only what the device knows — impression caps, dismissal, cooldown. Shipping the
predicates would mean two implementations of the same rules drifting apart, and the client's
copy losing, since it cannot see screens, cohorts or rollout buckets at all.

### Unknown displays render nothing

`DisplayType.from()` returns `null` for an unrecognized value instead of falling back to
`DIALOG`. This closes two cases: `display: "none"` (a value-only feature flag could previously
have shown a modal) and any presentation the control plane adds later, which reaches an older
SDK as an unknown string.

## Required

- `X-RC-SDK-Version` is always sent. The server answers `403 sdk_version_missing` rather than an
  empty set, so a client that omits it is blacked out entirely.
- `multiplatform-settings-no-arg` is now a declared dependency. It had been arriving transitively
  through supabase-postgrest.

## Why this is not on Maven

Two gates, both open:

1. **Repo invariant 6** — KmpToolkit still publishes `cmp-remote-config[-compose]`. Publishing
   from here as well would have two repositories racing the same coordinate.
2. **Epic gate G-11** — no operator has yet driven the dashboard end to end. As of 2026-10-07 the
   deployed plane holds 15 builtin templates and **zero apps, keys or configs**. Shipping an SDK
   whose control plane has never been operated by a human would be shipping on inference.

The live wire contract IS verified: `supabase/tests/e2e_sdk_contract.sh` seeds a sentinel on the
deployed project, fetches through the real edge function, and parses the response with the
production model under a strict reader.
